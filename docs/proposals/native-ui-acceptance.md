# Native edit, reopen and MP4 export

Last updated: 2026-11-12

The recorder brief requires usable native editing and export, which its closed
30-case synthetic composition/player scope and universal preview do not prove.
Alvaro's standing “I approve everything / Keep going / Do all the work” covers
this newly concrete native UI and temporary public CI scope. This is separate
from the earlier non-launching packaging approval. No old accepted tests or
packaging run is replayed, and no product source change is proposed initially.

One FUI01 XCTest UI journey launches a fresh ARM64/macOS 15 Debug build of the
actual app. A new Xcode UI target compiles unchanged app sources and the existing
FrameletCore package, with the production bundle metadata/icon and empty ad-hoc
entitlements. It adds no dependency, team, account, hosted service or paid plan.

The owned runner's default app library must be absent before the controller
creates it with a nonce and inode binding. No HOME override or test-only app
entrypoint is used. The host CI fixture tool writes two short solid-colour
H.264 sources and a valid ready recording before launch. XCTest stays within
its existing sandbox, using only native controls/visible state; it does not
read or write the app library. The controller already owns that fresh library
and runs its separate fixture tool under its existing host permissions. No
sandbox, entitlement, privilege or access grant changes. Actual edits occur
through native controls: rename, trim, duplicate, reorder, remove from edit and
apply square/sand canvas. XCTest exports through NSSavePanel, terminates and
reopens the app, and observes persisted title, clip ranges and enabled preview.
The host tool then independently reads the saved manifest, verifies original
media hashes, and decodes the actual MP4 to check 1080-square geometry, duration
and blue/red frames across the edited boundary. Both UI and file proofs must
pass; neither can substitute for the other.

The app never selects a capture source, starts recording or enables camera,
microphone or system audio. There are no device prompts, screen enumeration,
real-user files, Trash, network/model calls or signing enrollment. App-window
screenshots and accessibility trees cover four actual phases and failure state.
This proves only generated-media editing/export when it passes, not live
capture timing/audio/PiP, preview playback quality, Intel execution, physical
devices, Gatekeeper or trusted distribution. Those original requirements stay
open, with their prior source boundaries preserved.

Local Storage Guard measured 0.2 GiB free against 34.0 GiB required; no local
build, app, test, simulator or capture execution is permitted. Source/XML/Python
syntax and whitespace checks are safe. One temporary public macos-15 job is
capped at 20 minutes, with Xcode 16.4, a 15-minute native-controller budget,
per-command deadlines and 2 MiB output streams. Only current app/resource/core
and UI-target source is exported, along with the existing test-target files
needed to resolve the package manifest (not executed). No repo history or
historical audit tree is copied.

The [inactive workflow](native-ui-acceptance.workflow.yml.example) pins the
published source. Complete command streams, native test summary/identity,
attachments and decoded output evidence are bounded and retained, including
failures. The controller terminates only owned app/runner processes, verifies
source bytes, deletes only its nonce/inode-bound fresh library and scratch.
Large automatic videos remain in the bounded uploaded packet; diagnostic
PNGs/trees/JSON have a separate 8 MiB inline capsule. Failed raw xcresult bundles
are retained. After a fully passing UI/file/cleanup verdict, the raw bundle
intermediate may be removed because its exported original attachments, complete
command streams and Apple summary/identity records are already retained; this
does not claim preservation of that passing raw bundle's internal database.
Evidence upload is bounded at 128 MiB and retained separately; its exact server
digest/run identity is verified before removing the uploaded runner packet.
The final control disables its own workflow and deletes its unchanged QA head.
Canonical compact receipts, originals and visual review belong in
`docs/results/2026/11-12/`, not an acceptance claim based only on CI status.
